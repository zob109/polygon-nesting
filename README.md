# 多边形排样求解器 · 过程可视化

把二维多边形排样（nesting）求解器的每一步拆成可播放的帧：它能一块一块地把多边形放进边界里，
也能直接改输入数据重新跑一遍。纯静态前端，不需要后端。

- **问题**：给定一个边界多边形和若干小多边形，每个小多边形**只能平移**，
  要求两两不重叠、全部落在边界内，并让总位移 **Σ|trans|** 尽量小。
- **算法**：三角剖分 + BVH → NFP 凸包近似 → 顺序放置 → 全局压缩 → 模拟退火。
- **实现**：从 C++ 求解器移植到 JavaScript，直接在浏览器里跑，无需编译。

## 五个阶段

| 阶段 | 做了什么 | 在页面上能看到什么？ |
|---|---|---|
| 预处理 | 按形状去重、耳切法三角剖分、建 BVH、建边界网格索引 | 形状个数与三角形个数 |
| 排序筛选 | 用 20 种启发式（面积 / 周长 / 凹陷度 / 初始位置……）各跑一遍，取最好的顺序 | 右侧「放置顺序对比」表 |
| 顺序放置 | 逐个多边形搜索合法且最近的位置：NFP 顶点 → 边采样 → 网格种子 → 约束边交点 | 每帧放下一个，蓝点是被搜索过的合法落点 |
| 全局压缩 | 所有多边形同时朝原点收缩，二分搜索可行距离 | 整体往里挤 |
| 模拟退火 | 扰动放置顺序，温度 2000 → 0.02，接受更优解 | 有改进时插入一帧 |

## 输入格式

第一行是边界多边形顶点数，第二行是它的坐标；接着是多边形数量，再逐个给出
「顶点数 + 坐标」。坐标是 `x y` 交替的浮点数。

```
4                        ← 边界顶点数
0 0  10 0  10 10  0 10   ← 边界顶点（建议逆时针）
6                        ← 多边形数量
4                        ← 第 1 个多边形的顶点数
0 0  3 0  3 2  0 2       ← 第 1 个多边形的顶点
4
...
```

也可以直接喂给 `tools/verify.js` 做命令行校验。

## 本地运行

因为用到了 Web Worker，`file://` 直接双击会被浏览器的同源策略拦住（页面会自动退回单线程模式，
能用但会卡住界面几秒）。建议起一个本地服务器：

```bash
cd polygon-nesting
python -m http.server 8000
# 打开 http://localhost:8000
```

访问 [https://zob109.github.io/polygon-nesting/](https://zob109.github.io/polygon-nesting/)

## 加自己的算例

**页面里加**（存在浏览器 localStorage，不上传）：改文本框 → 点「添加」→ 起个名字。
之后可以随时在下拉框里切换、删除、导出 `.in`。

**代码里加**（对所有访客可见）：编辑 `assets/data.js`，往 `NEST_DATASETS` 里追加一项：

```js
{
  id: 'my-case',
  name: '我的算例',
  note: '一句话说明',
  text: `...输入文本...`
}
```

## 两个引擎

页面右下角可以切换引擎，两者跑的是同一个问题，但不是同一份代码：

| 引擎 | 是什么 | 耗时 | Σ\|trans\| |
|---|---|---|---|
| **原版 C++（WASM）** | `Solution.cpp` 原样编译成 WASM，帧来自它自己的 `saveFrame()` | 约 12 / 20 / 57 s | 635.17（8 s 档） |
| **JS 快速预览** | 我做的 JS 移植，帧是运行时算的，支持候选点/原位虚线等叠加 | 约 2 s | 637.97 |

原版引擎只改了三处（开可视化、时限可从命令行传、固定输出目录），算法一行没动。
diff 见 [`wasm/changes.patch`](wasm/changes.patch)，说明见 [`wasm/README.md`](wasm/README.md)。

**建议**：想看真实求解过程用原版；想快速改参数试算例用 JS 预览。

## JS 移植与原版的差异

1. **NFP 用 Minkowski 和代替暴力凸包**：对两条凸包做边向量归并，O(n+m)。
   与原实现「所有两两差值取凸包」数学上等价，已用 80 组随机形状对验证（误差 < 1e-9）。
2. **边界内含判定加了均匀网格索引**：只用于减少候选边，判定逻辑与 C++ 一致。
3. **严格 inner-NFP 未移植**：原版用栅格化 + Moore 轮廓追踪算出贴着边界的候选种子，
   这里改用边界顶点 + 网格种子。这是解质量差距的主要来源，但不影响合法性。
4. **候选按距离升序检查**：找到第一个合法位置即停，等价于在同一候选集上取最小 |trans|。
5. **退火用低成本评估**：对应原实现的 fast/full 两级漏斗。

## 结果校验

求解器自带的判定和校验如果共用同一段代码，一旦那段代码有 bug，两边会一起给出"通过"——
这个项目就踩过这个坑。所以页面上的最终校验走**另一套方法**：

- 边界：沿多边形每条边按 0.02 步长密集采样，逐点做射线法（求解器用的是"边相交 + 单个内部点"）
- 重叠：对每对包围盒相交的多边形做三角形 SAT，取最小分离间隙，容差 1e-6

命令行还有一份纯 Python 的独立实现，和 JS 完全不共享代码：

```bash
python tools/check_solution.py data/default.in reference/cpp_out_default.txt
```

`reference/cpp_out_default.txt` 是原始 C++ 编译后实跑的结果（详见 `reference/README.md`）。

## 修正记录

**v1 的解不合法。** 第一版为了提速，把「同一条边界边在一次查询内只检测一次」的去重表
提到了内边循环外面。但一条边界边必须和**每一条**内边都比较——结果真正相交的那条内边被跳过，
相交检测整体失效，最后只靠"内部点是否在边界内"放行。默认算例上 100 个多边形有 **38 个越界**，
最大越界深度 0.70，而 Σ|trans| 虚低到 597.9。

修法是把去重表按内边重置；同时把判定点从"包围盒中心"改成"第一个三角形的重心"，
因为凹多边形的包围盒中心可能落在自己外面，也可能正好压在边界顶点上（射线法在顶点上结果不确定）。

## 求解强度

| 预设 | 候选采样步长 | 比较顺序数 | 退火迭代 | 默认算例耗时 |
|---|---|---|---|---|
| 快速 | 0.5 | 6 | 8 | ~2.2 s |
| 标准 | 0.2 | 8 | 10 | ~3.8 s |
| 彻底 | 0.06 | 16 | 40 | ~7 s |

耗时是 Node 22 下的实测值，浏览器里接近。

## 键盘

`空格` 播放 / 暂停，`←` `→` 上一帧 / 下一帧，`Ctrl/Cmd + Enter` 重新求解。
